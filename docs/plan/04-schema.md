# Step 04 — Schema (Ecto.Schema)

**Depends on:** 03. **Parallel with:** 07, 11.
**Owns:** `packages/core/src/schema/`, `packages/core/test/support/blog.ts`,
`benchmarks/micro/schema.bench.ts`, `docs/site/guide/schemas.md`.

## Goal

The `Schema()` class factory, the `t` field builder, association and embed declarations,
row construction, and all schema-derived types. Read `spikes/schema-typing.ts` first: it
is the proven skeleton of the type design, and its assertions become your type tests.

## Public API

```ts
import { Schema, EmbeddedSchema, t, timestamps, hasMany, hasOne, belongsTo, manyToMany,
         type Row, type InsertShape, type Loaded, meta } from "ectype";

class User extends Schema("users", {
  id: t.id(),                                   // primary key, database-generated
  email: t.string(),
  name: t.string().nullable(),
  role: t.enum(["admin", "member"]).default("member"),
  loginCount: t.integer().default(0),
  password: t.string().virtual(),
  passwordHash: t.string().redact().source("pw_hash"),
  settings: t.json<{ theme: string }>().nullable(),
  lockVersion: t.integer().default(1),
  ...timestamps(),                              // insertedAt, updatedAt (utcDatetime, autogenerated)
}, { prefix: undefined, naming: "snake_case" }) {
  static profile  = hasOne(() => Profile, { foreignKey: "userId" });
  static posts    = hasMany(() => Post, { foreignKey: "authorId", preloadOrder: ["insertedAt"] });
  static comments = hasMany(() => Comment, { through: ["posts", "comments"] });
  static tags     = manyToMany(() => Tag, { joinThrough: "users_tags", joinKeys: { userId: "id", tagId: "id" } });

  get displayName() { return this.name ?? this.email; }   // plain class members are allowed
}

const u = new User({ email: "a@b.c" });   // defaults applied; state "built"
meta(User).source;                         // "users"
```

### Field builder `t`

`t.<type>(opts?)` for every type in step 03, plus `t.type(customType)`. `t.id()` is
`integer` + `primaryKey()` + `readAfterWrites()`; `t.uuid().primaryKey().autogenerate()`
gives a client-generated UUID key (v7 by default: index-friendly; option for v4).

Chainable modifiers; each returns a new builder and narrows the builder's type flags:

| Modifier | Effect | Ecto equivalent |
|---|---|---|
| `.nullable()` | adds `\| null` to the row type; default becomes `null` | (Ecto default) |
| `.default(v \| () => v)` | value for `new S()`; optional in `InsertShape` | `default:` |
| `.primaryKey()` | part of the primary key (composite allowed) | `primary_key: true` |
| `.autogenerate(fn?)` | client-side value on insert when unset | `autogenerate:` |
| `.virtual()` | not persisted, not selected | `virtual: true` |
| `.source("col")` | column name override | `source:` |
| `.redact()` | hidden in inspect / `toJSON` / logs | `redact: true` |
| `.readAfterWrites()` | include in `RETURNING` on insert/update | `read_after_writes: true` |
| `.writable("always" \| "insert" \| "never")` | restricts writes | `writable:` |

`timestamps({ insertedAt?: name | false, updatedAt?: name | false, type? })` returns a
fields fragment to spread.

### Associations

All take a thunk and options, and are declared as `static` members (D1). Keys in options
are **field names**, not column names.

- `belongsTo(() => T, { foreignKey = "<name>Id", references = <T's pk>, optional? })`
- `hasOne / hasMany(() => T, { foreignKey = "<ownerName>Id", references = <own pk>, where?, preloadOrder?, onReplace?, onDelete?, through? })`
- `manyToMany(() => T, { joinThrough: "table" | (() => JoinSchema), joinKeys, where?, joinWhere?, onReplace?, unique? })`
- `through: ["assocA", "assocB"]` builds a has-through association (read-only).

Validation happens once, lazily, the first time `meta(S).assocs()` is called (targets are
not defined at class-creation time): the foreign key must exist on the right schema with a
compatible type, `through` paths must resolve, names must not collide with fields. Failures
throw `SchemaDefinitionError` naming schema, association and the fix.

### Embedded schemas

`class Address extends EmbeddedSchema({ street: t.string(), city: t.string() }) {}` and
field builders `t.embedOne(() => Address)` / `t.embedMany(() => Address)` (stored as jsonb;
option `{ onReplace }`). This step defines them and their types; casting and persistence
are step 15.

### Types

- `Row<S>` = `InstanceType<S>`: fields only (virtual fields included, associations excluded).
- `InsertShape<S>`: fields required unless nullable / defaulted / autogenerated / readAfterWrites; virtual excluded.
- `Loaded<S, P>`: `Row<S>` plus preloaded associations. `P` is a union of keys or a nested
  spec `{ posts: "comments" | { comments: "author" } }`. `hasMany`/`manyToMany` become
  `Row<T>[]`, `hasOne`/optional `belongsTo` become `Row<T> | null`, required `belongsTo`
  (non-null FK) becomes `Row<T>`.
- Accessing a non-preloaded association on a plain `Row<S>` is a **compile error**
  (the property does not exist). This replaces Ecto's `%NotLoaded{}`.

## Behaviour

1. **Class creation.** `Schema(source, fields, opts)` returns a base class with
   `[META]: SchemaMeta` built eagerly for fields and lazily for associations. Detect
   static associations by scanning own static properties of the *subclass* for association
   markers on first `assocs()` call. Reject at definition time: no primary key (unless
   `{ primaryKey: false }`), duplicate columns, reserved field names (`constructor`,
   `__proto__`, `toJSON`, anything starting with `$`).
2. **Row shape.** Every instance has every declared field as an own property, assigned in
   declaration order, then one symbol-keyed `[ROW]` property. Never add or delete
   properties afterwards. Verify monomorphism in a benchmark (`%HaveSameMap` under
   `--allow-natives-syntax` in a dedicated test).
3. **`new S(init?)`.** Applies defaults (calling function defaults), `null` for nullable
   fields without default, `undefined` for required fields without default, then `init`
   (unknown keys throw). State `built`. Does not run autogenerate; that happens on insert.
4. **Row factory.** `meta(S).create(values)` builds a `loaded` row from a positional
   array in `persisted` order, without calling the user-visible constructor path's default
   logic. Implement with a generated function (`new Function`) when available and a loop
   fallback when CSP forbids eval (detect once; option `{ codegen: false }` forces the
   fallback; both paths tested).
5. **`toJSON` and inspect.** Rows serialise as plain objects of their fields; redacted
   fields are omitted from `toJSON` and shown as `**redacted**` in `util.inspect`.
   `toJSON` lives on the prototype (not per row).
6. **Helpers.** `meta(S)`, `isSchema(x)`, `isRow(x)`, `stateOf(row)`, `primaryKeyOf(row)`,
   `fieldNames(S)`, `S.fields` for reflection.
7. **Reference schemas.** Implement the full blog domain from step 01 in
   `test/support/blog.ts` (User, Profile, Post, Comment, Tag, Org, Membership), covering
   every association kind, a composite key, a uuid key, an enum, a virtual and a redacted
   field, and an embed. All later steps test against these.

## Tests

- Type tests (the largest part of this step): port every assertion from the spike; then
  `Row`, `InsertShape` (each modifier combination), `Loaded` (each association kind,
  nested two and three levels, union of keys, invalid key rejected), enum literal unions,
  embeds, getters on subclasses preserved in query results, self-referential and mutually
  recursive schemas compile.
- Unit: metadata for each modifier; naming strategy; `source` override; defaults (value
  vs function, fresh object per instance); unknown init keys; every `SchemaDefinitionError`;
  lazy association resolution with out-of-order module definitions; factory codegen and
  fallback produce identical rows; `toJSON` redaction.
- Benchmarks: `new User()`, factory creation of a 10-field row (budget < 150 ns), `meta()` lookup.
