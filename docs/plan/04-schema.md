# Step 04 — Schema

**Depends on:** 03. **Parallel with:** 07, 11.
**Owns:** `packages/core/src/schema/`, `packages/core/test/support/blog.ts`,

## Goal

The `Schema()` class factory, the `t` field builder, association and embed declarations,
row construction, and all schema-derived types. Read `spikes/schema-typing.ts` first: it
is the proven skeleton of the type design, and its assertions become your type tests.

## Public API

```ts
import { Schema, EmbeddedSchema, t, timestamps, hasMany, hasOne, belongsTo, manyToMany,
         type Row, type InsertShape, type Loaded, meta } from "egon-orm";

class User extends Schema("users", {
  id: t.integer().primaryKey(),                 // primary key, database-generated
  email: t.string(),
  name: t.string().nullable(),
  role: t.enum(["admin", "member"]).default("member"),
  loginCount: t.integer().default(0),
  password: t.string().virtual(),
  passwordHash: t.string().redact().column("pw_hash"),
  settings: t.json<{ theme: string }>().nullable(),
  lockVersion: t.integer().default(1),
  ...timestamps(),                              // createdAt, updatedAt (timestamp, autogenerated)
}, { schema: undefined, naming: "snake_case" }) {     // `schema` = database schema (was `prefix`)
  static profile  = hasOne(() => Profile, { foreignKey: "userId" });
  static posts    = hasMany(() => Post, { foreignKey: "authorId", orderBy: ["createdAt"] });
  static comments = hasMany(() => Comment, { through: ["posts", "comments"] });
  static tags     = manyToMany(() => Tag, { joinThrough: "users_tags", joinKeys: { owner: "user_id", target: "tag_id" } });

  get displayName() { return this.name ?? this.email; }   // getters and methods only
}

meta(User).source;                         // "users"
// There is no public constructor (plan README D2). Rows come from the database; a new
// record is a changeset: cast(User, params, [...]) or change(User, values) (step 05).
```

### Field builder `t`

`t.<type>(opts?)` for every type in step 03, plus `t.type(customType)`. `t` is the only
public namespace for types; a builder exposes its `FieldType` so that `param`, `expr.cast`,
`values` and schemaless changesets can take a builder. There is **no `t.id()`**: a key is
`t.integer().primaryKey()` (or `t.bigint({ mode: "number" }).primaryKey()` for a 64-bit
column) and a foreign key is a plain `t.integer()`. `.primaryKey()` on an integer or
bigint implies `dbGenerated()`; `.primaryKey({ dbGenerated: false })` opts out (natural
keys). `t.uuid().primaryKey().autogenerate()` gives a client-generated UUID key (v7 by
default: index-friendly; option for v4) and is not database-generated.

Chainable modifiers; each returns a new builder and narrows the builder's type flags:

| Modifier | Effect | Ecto equivalent (for workers; not for user docs) |
|---|---|---|
| `.nullable()` | adds `\| null` to the row type; default becomes `null` | (Ecto default) |
| `.default(v \| () => v)` | value used for a new record when none is given; optional in `InsertShape` | `default:` |
| `.primaryKey(opts?)` | part of the primary key (composite allowed); integer and bigint keys are database-generated unless `{ dbGenerated: false }` | `primary_key: true` |
| `.autogenerate(fn?)` | client-side value on insert when unset | `autogenerate:` |
| `.virtual()` | not persisted, not selected | `virtual: true` |
| `.column("col")` | column name override | `source:` |
| `.redact()` | hidden in inspect / `toJSON` / logs | `redact: true` |
| `.dbGenerated()` | the database produces the value; include in `RETURNING` on insert/update | `read_after_writes: true` |
| `.writable("always" \| "insert" \| "never")` | restricts writes | `writable:` |

`timestamps({ createdAt?: name | false, updatedAt?: name | false, type? })` returns a
fields fragment to spread.

### Associations

All take a thunk and options, and are declared as `static` members (D1). Keys in options
are **field names**, not column names.

- `belongsTo(() => T, { foreignKey = "<property name>Id", references = <T's pk> })`. There is
  no `optional`: the result is `T | null` exactly when the foreign-key field is `.nullable()`.
- `hasOne / hasMany(() => T, { foreignKey, references = <own pk>, where?, orderBy?, onReplace?, through? })`.
  **`foreignKey` is required** (unless `through` is given): a default derived from the
  owner's class name would break when a bundler minifies class names. There is no
  `onDelete` option (it did nothing).
- `manyToMany(() => T, { joinThrough: "table" | (() => JoinSchema), joinKeys?, where?, joinWhere?, onReplace?, unique? })`.
  With a table name, `joinKeys` is `{ owner, target }` holding the join table's **column**
  names, and it is **required** (owner decision, 2026-10-13): there is no default, because
  one would need the class name (unsafe under minification) or singularising the table
  name. Omitting it is a compile error and a `SchemaDefinitionError`.
  With a join schema, `joinKeys` holds that schema's field names and may be omitted when
  the join schema declares `belongsTo` associations to both sides.
- `through: ["assocA", "assocB"]` builds a has-through association (read-only).

Validation happens once, lazily, the first time `meta(S).assocs()` is called (targets are
not defined at class-creation time): the foreign key must exist on the right schema with a
compatible type, `through` paths must resolve, names must not collide with fields. Failures
throw `SchemaDefinitionError` naming schema, association and the fix.

### Embedded schemas

`class Address extends EmbeddedSchema({ street: t.string(), city: t.string() }) {}` and
field builders `t.embedOne(() => Address)` / `t.embedMany(() => Address)` (stored as jsonb;
option `{ onReplace }`). This step defines them and their types; casting and persistence
are step 15.

### Types

- `Row<S>` = `S extends abstract new (...args: never[]) => infer R ? R : never` (the instance
  type for a concrete class; `object`, not `any`, for `AnySchema`): fields only (virtual fields included, associations excluded).
- `InsertShape<S>`: fields required unless nullable / defaulted / autogenerated / dbGenerated; virtual excluded.
- `Loaded<S, P>`: `Row<S>` plus preloaded associations. `P` is a union of keys or a nested
  spec `{ posts: "comments" | { comments: "author" } }`. `hasMany`/`manyToMany` become
  `Row<T>[]`, `hasOne`/`belongsTo` over a nullable foreign key become `Row<T> | null`, `belongsTo`
  (non-null FK) becomes `Row<T>`.
- Accessing a non-preloaded association on a plain `Row<S>` is a **compile error**
  (the property does not exist). This replaces Ecto's `%NotLoaded{}`.

## Behaviour

1. **Class creation.** `Schema(source, fields, opts)` returns a base class with
   `[META]: SchemaMeta` built eagerly for fields and lazily for associations. Detect
   static associations by scanning own static properties of the *subclass* for association
   markers on first `assocs()` call. Reject at definition time: no primary key (unless
   `{ primaryKey: false }`), duplicate columns, reserved field names (`constructor`,
   `__proto__`, `toJSON`, anything starting with `$`).
2. **Row shape.** Every instance has every declared field as an own property, assigned in
   declaration order, then one symbol-keyed `[ROW]` property. Never add or delete
   properties afterwards. Verify monomorphism in a benchmark (`%HaveSameMap` under
   `--allow-natives-syntax` in a dedicated test).
3. **No public constructor.** Developers never write `new S(...)`, and the row factory never
   runs a constructor, so a subclass constructor or field initialiser would silently not
   run: the guide says that schema classes carry getters and methods only. Calling the
   constructor directly throws `SchemaDefinitionError` pointing at `cast(S, ...)` /
   `change(S, ...)`. Defaults (value or function, a fresh value per record) are exposed on
   the metadata; step 05 reads them for `getField` on a new-record changeset and step 13
   applies them on insert. The row state `built` is no longer produced by user code.
4. **Row factory.** `meta(S).create(values, rowMeta)` builds a row from a positional
   array in `persisted` order and stores `rowMeta` under `[ROW]`; `meta(S).rowMeta(state, schema)`
   returns the shared frozen `RowMeta`, and `meta(S).createWith(assocs)` is the factory
   variant for rows that carry preloaded associations (step 14). `[META]` on the class,
   `fields` on the metadata and the members of each `FieldMeta` are own data properties,
   never getters (`contracts/schema.ts`). `create` works without calling the user-visible constructor path's default
   logic. Implement with a generated function (`new Function`) when available and a loop
   fallback when CSP forbids eval (detect once; option `{ codegen: false }` forces the
   fallback; both paths tested).
5. **`toJSON` and inspect.** Rows serialise as plain objects of their fields plus any
   preloaded associations (recursively; owner decision, 2026-10-13); redacted
   fields are omitted from `toJSON` and shown as `**redacted**` in `util.inspect`.
   `toJSON` lives on the prototype (not per row). Redaction applies at every level of a
   preloaded tree.
6. **Helpers.** `meta(S)`, `isSchema(x)`, `isRow(x)`, `stateOf(row)`, `primaryKeyOf(row)`,
   `fieldNames(S)`, `S.fields` for reflection.
7. **Reference schemas.** Implement the full blog domain from step 01 in
   `test/support/blog.ts` (User, Profile, Post, Comment, Tag, Org, Membership), covering
   every association kind, a composite key, a uuid key, an enum, a virtual and a redacted
   field, and an embed. All later steps test against these.

## Tests

- Type tests (the largest part of this step): port every assertion from the spike; then
  `Row`, `InsertShape` (each modifier combination), `Loaded` (each association kind,
  nested two and three levels, union of keys, invalid key rejected), enum literal unions,
  embeds, getters on subclasses preserved in query results, self-referential and mutually
  recursive schemas compile.
- Unit: metadata for each modifier; naming strategy; `source` override; defaults (value
  vs function, fresh value per call) as exposed on the metadata; the constructor guard; every `SchemaDefinitionError`;
  lazy association resolution with out-of-order module definitions; factory codegen and
  fallback produce identical rows; `toJSON` redaction.
- Benchmarks: factory creation of a 10-field row (budget < 150 ns), `meta()` lookup.
