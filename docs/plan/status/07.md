## Decisions

1. **`between` has a node kind of its own**, `BetweenNode { kind, expr, low, high }`
   (`x BETWEEN low AND high`), added to `ExprNode` in `contracts/query.ts`. Writing it as
   `x >= a AND x <= b` would repeat `x` and its params, and the guide gives the SQL as
   `BETWEEN`. The contract README named this as the open point; it lets step 07 refine
   expression nodes, and adding a kind is the smallest such refinement. The contract's
   exhaustive-switch type test lists the new kind.
2. **A `CASE` branch is `{ when, result }`**, not `{ when, then }`. An object literal with
   a `then` member is a thenable (Biome's `noThenProperty`, enforced here): `await`ing
   anything that holds one would call it. Renamed in the contract (`CaseNode.whens`).
3. **`Expr<T, P>` carries the named parameters `P` it uses.** `param("minAge",
   t.integer())` is `Expr<number, { minAge: number }>`, and every operator and function
   merges the `P` of its operands (`and(…)`, `filter`, `caseWhen`, `fragment`, `in(query)`,
   …), so a `where` callback's result tells step 08 which params the query needs. Without
   it, `u.age.gte(param(…))` would lose the parameter's name. `T` and `P` are declared
   covariant (`out`). Methods whose result type depends on the operand's type (`lower`,
   `add`, `append`, `cast`, …) infer it from `this` (`this: Expr<S, object>`), which keeps
   `Expr` covariant: `Expr<string>` is an `Expr<string | null>`.
4. **"Each method exists only on fitting types" is a compile error, not an absent
   method.** Operators are on one class (no per-type subclasses, no `Proxy`, decision D8),
   and a method's `this` parameter restricts it: `u.age.ilike("x")` fails to compile with
   "The 'this' context … is not assignable". Editors still list the method. A per-type
   conditional type for `Expr` would hide them, at the cost of deferred conditional types
   in every generic helper a developer writes; I kept the simpler form.
5. **Operand types.** A value takes the type and `redact` flag of the other side, as the
   spec says, with these choices where "the other side" is not the right type: text
   patterns (`like`, `ilike`, `notLike`) and `concat` parts are bound as `string` (a
   pattern on an enum column is not an enum value; its `toDb` would refuse it); `has`,
   `append` and `remove` take the array's element type; JSON path keys are untyped
   parameters; `and(true)` binds a boolean. `contains`, `containedBy`, `overlaps` take
   the array type itself.
6. **`null`.** Comparisons (`eq` … `lte`, `between`, the elements of an `in` list, `has`)
   refuse `null` and `undefined` at compile time and with `QueryError` at run time, also
   when the `null` is an explicit `val(null)`. `isDistinctFrom` takes `null` (that is its
   purpose). Every other operator refuses `null` and `undefined` with its own message.
   `append` and `remove` take a `null` element (`array_remove(tags, NULL)` is meaningful).
7. **`in([])` is the literal `FALSE` and `notIn([])` `TRUE`, built when the expression is
   built**, with no parameter, so the left side (and its params) are dropped. A list is
   copied when the expression is built, so that changing the caller's array later cannot
   change the query or put `lists` out of step with it.
8. **`a.and(b).and(c)` is one flat `and`**; mixing `and` and `or` nests. `and()` is
   `TRUE`, `or()` `FALSE`, and `and(x)` is `x` itself.
9. **Aggregate result types and how they are loaded.** `count` is loaded with
   `bigint({ mode: "number" })` (the database returns a 64-bit integer). `sum` over an
   integer column is loaded the same way (the database widens the sum); over anything else
   with the argument's type. `avg` over numbers is emitted as `CAST(avg(x) AS float)` and
   typed `number`: the database computes the average as a decimal, which the driver
   returns as a string, and the spec types it `T | null`. `avg` over `t.decimal()` stays a
   decimal string, unwrapped. `filter` and `over` keep the cast. `min` and `max` keep the
   argument's type; `arrayAgg` is `T[] | null`; `jsonAgg` is `unknown[] | null` (values
   come back as JSON, so a `Date` is a string). `sum` and `avg` take
   `number | bigint | string` (decimals are strings) and refuse a known non-numeric type
   at run time.
10. **`filter` and `over`.** A second `filter` is ANDed with the first. `over()` is the
    whole result, `over("w")` a named window, `over({ partitionBy, orderBy, frame })` an
    inline one (`frame` must be a fragment; a bare expression in `orderBy` is ascending).
    `over` twice is a `QueryError`. Checking a window name against the query's declared
    windows is step 09's.
11. **`coalesce(first, ...rest)`** needs an expression first (it gives the type plain
    values are bound with) and at least two arguments; every argument must fit `first`'s
    type.
12. **`caseWhen(cond, value)` is nullable until `.else(…)`**; a plain value is bound with
    the type of an earlier expression branch, untyped when there is none. Plain values'
    types are widened (`"minor"` is a `string`).
13. **`cast` keeps the operand's `null`** (`u.age.cast(t.string())` is `string | null`),
    except on an operand of type `unknown` (a fragment, a JSON path), where the result is
    the cast type: there is nothing to say it is nullable, and `as<T | null>()` states it.
14. **`as<T>()` returns the same expression** (no SQL, no allocation).
15. **`fragment`'s guard** accepts only a frozen array with a `raw` array of the same
    length, one more element than there are arguments, every element a string. A template
    strings array is frozen; an array built by hand to look like one is not. An
    interpolated query is a subquery; `null` is bound; `undefined` is refused.
16. **`val`**: without a type, the value's own type with literals kept (`val("member")` is
    `Expr<"member">`, so it can be compared with an enum column); with a type, the value
    must fit it (`NoInfer`). `val(undefined)` is refused. **`lit`** is
    `Expr<boolean | number | null>` and refuses everything else, `NaN` and infinities
    included.
17. **Errors are `QueryError`**, including a non-builder given where a field type is
    expected (`cast`, `val`, `param`), so that every misuse of the query API has one error
    class. Messages name the method and never contain a value.
18. **The subquery protocol.** A query becomes an operand through a method under the
    registered symbol `AS_SUBQUERY` (`Symbol.for("egon.asSubquery")`) that returns an
    `Expr` whose node is a `SubqueryNode`; `in`, `exists` and `fragment` call it.
    `SubqueryOperand<R, P>` types it, so `u.id.in(query)` checks the query's single value
    against `u.id`, and its params flow into `P`.
19. **Shape.** `shapeOf` defines the hash for every node kind and a whole query (the
    contract's "Shape" list: kinds, operators, names, identifiers, schemas, literal values,
    a parameter's type and `redact`; never values, list lengths, select constants or a
    preload's query). A parameter's type contributes its `name`; two types with one name
    are told apart by the plan cache's structural check. A query's shape is its 18
    per-property shapes folded in declaration order (`combineQueryShape`), a list property
    is a fold over its elements (so adding a clause is one fold), and the test
    `combineQueryShape(queryPropertyShapes(ast)) === shapeOf(ast)` pins that.
20. **`collectParams`** takes an optional `lists` array for `listLengths`, and skips a
    `PreloadNode` given directly as well as `QueryAst.preloads`.
21. **What an expression holds**: `node`, `type`, `redact`, `params`, `lists`, `shape`,
    assigned in that order by one constructor; `Col` adds `binding` and `field`, where
    `field` is the `FieldMeta` (not only its name: the builder's object form of `where`
    and error messages need the type and the column). `OrderExpr` holds `node`, `params`,
    `lists`, `shape` and the ordered expression's shape (for `nullsFirst`/`nullsLast`).
22. **`path` / `pathText`** are refused at compile time on scalar types (string, number,
    bigint, boolean, `Date`, bytes) and at run time on an expression whose known type is
    not JSON (`t.array()` columns, which the types cannot tell from JSON arrays). Keys are
    strings or whole numbers (array positions); at least one.
23. **Function names are keys of the compiler's tables**, camelCase, listed in
    `FUNCTION_NAMES` and `AGGREGATE_NAMES` (`arrayAppend` is `array_append` on Postgres).
24. **`redact` flows with the value**: arithmetic, text functions, `cast`, `append`,
    `remove`, `path`, `min`, `max`, `arrayAgg`, `coalesce` and `sum` of a redacted field
    are redacted, so a value compared with them is too; comparisons, `count` and `exists`
    are not. A named parameter used beside a redacted field becomes redacted.

## Known gaps

- **Arithmetic on decimals is not typed**: `t.decimal()` values are strings, and the
  arithmetic methods require `number | bigint`. A decimal column can be cast
  (`.cast(t.float())`) or summed and averaged (decision 9).
- **Window names are not checked** against the query's windows (step 09).
- **`path` on a `t.array()` column** compiles and is refused at run time (decision 22).
- **The 3-clause build budget** cannot be measured until step 08; the expressions' part
  of it is measured above.
- **Editors list every operator on every expression** (decision 4).
- **A selected parameter has no type** when given as a plain value with nothing to take
  one from (`caseWhen(c, "minor")`); Postgres needs a cast to bind such a parameter in a
  select list (step 10 owns that, see Requests).

## Requests

**Step 08 (query builder)**

- Make columns with `new Col(alias, fieldMeta)` (`query/expr.ts`), once per (schema, alias).
  Virtual fields have no column; leave them out of bindings.
- `Query` implements `[AS_SUBQUERY]()`, returning `new Expr(subqueryNode(ast), type,
  false, ast.params, ast.listLengths, shapeOfSubquery("subquery", ast.shape))`, where
  `type` is the single selected expression's type. `SubqueryOperand<R, P>` is the type to
  satisfy, with `R` the query's single value.
- A clause callback's result carries its named params in its type: `ParamsOf<X>` and
  `MergeParams<A, B>` (`query/expr.ts`) give `P`.
- Splice `expr.params` and `expr.lists` at the clause's canonical offset; extend the
  per-property shapes with `foldShape(previous, shapeOf(clauseNode))` (or the clause
  node's shape built from `expr.shape`, e.g. `BoolNode`'s), and recombine with
  `combineQueryShape`. Test `ast.shape === shapeOf(ast)` and `ast.params` equals
  `collectParams(ast)` on built queries.
- `isExpr(value)` tells an expression from a constant in a select. `OrderExpr` is the
  ordered item; a bare `Expr` in `orderBy` is ascending (`orderNode(expr.node, "asc", undefined)`).
- `toOperand(value, type, redact, method, comparison)` is the operand rule (value →
  typed, redacted parameter) for the object form of `where`.

**Step 09 (advanced queries)**

- Window functions are `aggregateNode(name, args, false, undefined, over)` inside an
  `Aggregate` (so they get `.over()`); add their names to the compiler's table.
- `selectedAsNode`, `tupleNode` and `subqueryNode` constructors exist; `tuple(...)`,
  `selectedAs(...)`, `scalar(...)` and `outerRef(...)` are yours.

**Step 10 (compiler)**

- Emit `between` (`BetweenNode`), and read a `CASE` branch's `result`.
- `has` is `right = ANY(left)` (the array is on the left). `in` / `notIn` take a list, a
  subquery or an array expression on the right (documented on `BinaryNode`).
- Function and aggregate names are the camelCase keys in `FUNCTION_NAMES` /
  `AGGREGATE_NAMES`.
- `jsonPath` keys are untyped parameters, strings or integers; on Postgres `#> ARRAY[$1, $2]`
  binds them as text.
- A parameter with no type may be selected (`caseWhen(c, "minor")`, `val("x")`); the
  select-list cast needs a fallback for it.
- `avg` over numbers arrives as `cast(aggregate avg, float)`.

**Steps 11 and 12 (adapter, repo reads)**

- `count` and `sum` of integers are loaded with `bigint({ mode: "number" })`, which reads
  a number, a bigint or a digit string. `sum` over a plain `t.bigint()` column is a
  Postgres `numeric`, loaded with the `bigint` type: the `pg` override for `bigint` must
  accept the digit string of a `numeric` as well as an `int8`.

**Step 15 (embeds)**

- `guide/embeds.md` shows `u.address.field("city")`: a typed path into an embed. `path`
  and `pathText` work on embed columns today; `field` is yours to add (a method on `Col`
  for embed fields, or a function).

**Step 19 (benchmarks)**

- `expr.bench.ts` takes the expression classes from `dist/internal.js` (`expr`,
  `expressions`): columns cannot be made through the public entry point.
