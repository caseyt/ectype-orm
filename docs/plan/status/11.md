## Decisions

Recorded for the owner's sign-off. Where there was an open choice I took the explicit
option.

1. **`createAdapter` is public.** A dialect package reaches core only through `egon-orm`
   (there is no `egon-orm/adapter` entry, and `dist/internal.js` is not published), so
   the factory must be exported. The driver-wrapper interfaces stay unnamed (spec):
   `@egon-orm/postgres` derives them from `Parameters<typeof createAdapter>`. TSDoc says
   applications call `postgres(...)` instead.
2. **Driver fixes per column kind, composed by core.** The spec has the dialect supply
   "type overrides". Writing `Codec`s directly in the dialect package would need
   `IDENTITY` (not public, and `index.test.ts` keeps it so) and would have to dispatch on
   the type (status 03: `bigint` and `bigint(number)` share a kind). Instead a dialect
   declares `DriverCodecs` (`{ bigint: { fromDb }, json: { toDb }, ... }`) and core
   composes each fix with the type's own conversions (`fix` before `fromDb`, `toDb` before
   `fix`; the identity is skipped by reference). Every type of a kind is right, custom
   ones and embeds included.
3. **Postgres values.** Per-statement result parsers (`types` in each query config and
   cursor), not pool-level and never global: `int8`, `numeric`, `date` stay text;
   `timestamp` is read as UTC wall time; `timestamptz` is parsed by us (offsets with
   seconds included), so a global `pg.types` change elsewhere in the process does not
   affect these kinds. Driver fixes: `int8` text to `bigint` (also the `numeric` of
   `sum(bigint)`); `Buffer` to a plain `Uint8Array` view; JSON serialised by us;
   `Date`s written as UTC text (`...+00` for `timestamptz`), independent of the process's
   zone (`pg` writes the local offset in hours and minutes, which loses the seconds of
   historic offsets such as year 1). `bigint(number)` gets `BigInt` then its own check.
4. **`ping()`, `poolStats()` and parameter opt-in live on `DatabaseAdapter`**, not on the
   contract (as the carried-over note asked). Parameters reach a `query` listener only if
   it subscribed with `{ params: true }`; others get `params: undefined`. This is how
   step 12's `log: { params: true }` maps onto the adapter, with no adapter option.
5. **A throwing listener** does not fail the statement or stop other listeners; its error
   is rethrown on a microtask, so it surfaces as an uncaught exception instead of being
   swallowed (packages may not log).
6. **Cancellation.** `signal` / `timeoutMs` send `pg_cancel_backend(pid)` over a
   short-lived second connection with the same settings (`pg` has no public API for the
   protocol's cancel request). The call rejects only after the statement has ended **and**
   the cancel request was delivered, so a late cancel cannot hit the next statement on that
   connection; the connection is then reused. It rejects even if the statement completed
   anyway (`cause` undefined); otherwise `cause` is the driver's error. A signal that has
   fired runs nothing; an abort while waiting for a connection stops the wait (the late
   connection goes straight back). Both together: one cancel request, the first reason
   wins.
7. **Streams.** `pg-cursor` is an optional peer loaded on the first stream; missing, it
   is a `QueryError` saying how to install it. Default `batchSize` 100. `timeoutMs`
   applies to each round trip of a stream. One `query` event per stream, when it ends,
   with the total row count and the time from opening to the end (consumer time
   included). A cursor read that fails or is cancelled, or a cursor that cannot be closed,
   closes the connection instead of reusing it; so does releasing a dedicated connection
   with a stream still open.
8. **Connections that are not reused:** a fatal error (normalised code `"connection"`),
   a connection still inside a transaction when it is returned (dedicated or pooled, as
   reported by `pg`'s transaction status), and the cases of decision 7.
9. **A pool you bring** is used as it is: no listeners besides `connect` / `remove`, no
   `error` listener (that is the owner's), its type parsers untouched (decision 3 makes
   that unnecessary), and `close()` does not end it. Connection options together with it
   are a `TypeError`. The cancel connection uses `pool.options`.
10. **Error mapping.** As specified, plus: `57014` (statement timeout, or a cancel from
    another session) is `"timeout"`; class `08`, class `28` (authentication), `57P01`
    (also `pg_terminate_backend`), `57P02`, `57P03`, `53300`, Node network codes and
    `pg`'s own connection messages are `"connection"`; anything else with a SQLSTATE is
    `"database"`. Our message repeats the database's only for classes whose messages
    never quote a value (`42`, `40`, `25`, ...); for the others (data exceptions above all)
    it points to `error.cause`. Errors that are not `pg`'s are returned unchanged.
11. **Options.** Unknown keys and wrong types throw `TypeError` when `postgres()` is
    called (JavaScript callers and typos); `undefined` counts as left out, so
    `connectionString: process.env.DATABASE_URL` compiles under
    `exactOptionalPropertyTypes` (found by the type-checked guide example). `pool`
    defaults to `{ max: 10 }`; other pool settings default to `pg`'s.
12. **`begin(options)`** writes Postgres's syntax (`begin isolation level serializable,
    read only, deferrable`, and `read write` / `not deferrable` for `false`) from a table;
    an isolation level missing from `capabilities.isolationLevels` is a `QueryError`,
    wrong types are a `TypeError`. Savepoint names must be non-empty strings without NUL.
13. **Misuse after close or release** is a `DatabaseError` with the code `"connection"`.
14. **A statement list without parameters** returns the last statement's result (`pg`
    reports one per statement).
15. **Capabilities** are all true, as specified, including `lateralJoin` (lateral joins
    are future work in the builder; the flag only says Postgres can do them);
    `maxParams` 65,535.
16. **`poolExhausted`** fires when a checkout has to wait (no idle connection and the pool
    at `max`); the pool is asked only when someone listens.

## Deviations from the spec

- **`compile*`** do not work yet (Acceptance, first box): the compiler is step 10's,
  which is not merged.
- **The leak check is per test file, not a global teardown** (Acceptance, last box).
- **`DriverConnection` has `cursor`, `cancel` and `inTransaction`** besides `query`
  (the spec lists `query` and `stream`): the shared adapter needs the cancel request and
  the transaction state, and owns the stream loop itself (batches, early exit, abort).
  `DriverWrapper` also has `stats` and `saturated`.
- **The dialect gives `DriverCodecs`, not a `typeOverrides` function** (decision 2). The
  adapter's `typeOverrides` is still the contract's function.
- **`ConstraintError.sql`** was added in `packages/core/src/errors.ts` (not owned by this
  step): the spec says to attach the SQL to normalised errors and the guide's errors page
  says errors contain it, but only `DatabaseError` had a field for it. An optional
  constructor detail and a read-only member; nothing else changed. One test added in
  `errors.test.ts`.
- **`docs/site/package.json`, `docs/site/tsconfig.json`** gained `@egon-orm/postgres`,
  `pg` and `@types/pg` and a project reference, so that the guide's Postgres examples are
  type-checked (plan README §8).
- **Driver choice (item 11): `pg` only.** A second wrapper over postgres.js is not worth
  its upkeep now: `pg` is what the Drizzle, Sequelize and Prisma (driver adapter) users
  this library targets already run, postgres.js has its own pool, type handling, cursor
  and cancel semantics (a second set of every decision above), and nothing in the plan
  needs it. Future work, behind the same options, if users ask.

## Known gaps

- The conformance suite runs on Postgres 14 only on my machine; CI has 16 only.
- Not exercised against a database: SSL connections, Unix-socket hosts, a `password`
  function, `idleTimeoutMs`.
- A cancel request needs a free connection slot on the server. With `max_connections`
  exhausted it fails, the statement runs to its end, and only then does the call reject
  (by design, decision 6; not tested against a database).
- `timestamp` / `timestamptz` values `infinity` and `-infinity` come back as the numbers
  `Infinity` / `-Infinity`, as `pg` reports them; the timestamp types do not handle them.
- Benchmarks: none (step 19).

## Requests

**Step 10 (compiler and plan cache)**

- Wire `createStatementCompiler` in `packages/core/src/adapter/compiler.ts` to the
  compiler: one compiler, with its own plan cache of `planCacheSize` entries, per adapter
  instance. It receives `{ dialect, capabilities, quoteIdentifier, planCacheSize }`.
  Whichever of us merges second does the wiring; the six `compile*` methods of the
  adapter already delegate. Delete `compiler.test.ts`'s "throws" cases then.
- The adapter's capabilities come from the dialect package (`POSTGRES_CAPABILITIES` in
  `@egon-orm/postgres`). If the dialect table in `compiler/dialect.ts` also carries
  capabilities, one of the two should be the source of the other.

**Step 12 (repo reads)**

- `createRepo` should accept a `DatabaseAdapter` (or check for `ping` / `poolStats`) to
  pass `repo.ping()`, `repo.poolStats()` through; map `log: { params: true }` to
  `adapter.on("query", fn, { params: true })`, and forward `connect`, `disconnect`,
  `poolExhausted`. Pass `slots: plan.slots` and `context` with every `execute`.
- Postgres streams work **without** a transaction (pg-cursor's portal lives in the
  implicit transaction of the extended protocol; tested in the conformance suite). The
  guide's repo page says the repo opens one for the life of a stream: that is not needed
  on Postgres, and holding a transaction open has a cost.
- `bindParams` should take conversions from `resolveCodec(type, adapter)`; with this
  adapter, `bigint` values are written as is (`pg` sends `toString()`), JSON and
  timestamps through the fixes.

**Step 16 (transactions)**

- A dedicated connection returned while still inside a transaction is closed, not
  pooled; `destroy()` is there for a failed `ROLLBACK`. `timeoutMs` on a statement inside
  a transaction cancels that statement only; the transaction is then aborted, as after
  any failed statement (a savepoint recovers it: tested).

**Step 17 (SQLite, MySQL)**

- A dialect package supplies an `AdapterDefinition`: a driver wrapper, capabilities,
  `quoteIdentifier`, `DriverCodecs`, an error normaliser; and runs
  `runAdapterConformance` with a profile (`test/profile.ts` in `@egon-orm/postgres` is the
  model). `beginSql` writes Postgres's `BEGIN` syntax; MySQL needs
  `SET TRANSACTION ...` plus `START TRANSACTION [READ ONLY]`, so `begin` will need a
  dialect hook (it is in `adapter/`, where dialect conditionals are allowed).

**Step 19 (benchmarks)**

- The spec's benchmarks (`execute("select 1")` against raw `pg`, 1,000 rows, telemetry on
  and off). `bigint({ mode: "number" })` reads through `BigInt` first under decision 2;
  if it shows, a per-type exemption (its own `fromDb` reads digits) is cheap to add.

**CI / step 21**

- Run the Postgres integration project against Postgres 14 as well as 16 (a second
  service in `docker-compose.yml` and a CI matrix entry); the acceptance asks for both.
