# Step 01 — Foundation: status

- **Branch:** `step/01-foundation`
- **Date:** 2026-10-11
- **Local environment:** macOS (Apple M2), Node v20.15.0 (also run under v22.23.1), pnpm 8.15.5

## Read this first

1. **Docker could not be used on the development machine.** The daemon answers
   `docker info`, but its image store returns I/O errors (`docker pull postgres:16-alpine`
   and `docker images` both fail with `input/output error` under `/var/lib/containerd`;
   the host disk is 98% full). I did not restart, prune or reset Docker, because another
   project's database container is running in it. Consequences:
   - `pnpm db:up` / `db:down` / `db:reset` were **not run locally**. `docker compose config`
     validates the file, and the CI `integration` jobs run `pnpm db:up` and
     `pnpm db:up:tier2` for real (see "CI" below).
   - The integration tests were run locally against a real PostgreSQL 16.14 server started
     from the `embedded-postgres` npm package in a scratch directory outside the repository,
     on the same port, user, password and server flags as `docker-compose.yml`.
   - The MySQL half of the test support (`withDatabase("mysql")`, `truncateAll` on MySQL)
     was **not run locally at all**. It runs only in the CI job `integration (tier 2)`.
2. **Node 20 is the floor (D14) and it constrains the toolchain.** Several current releases
   no longer run on Node 20, so they are held back (table below). The most important one:
   the current Kysely minor is 0.29, which requires Node >= 22, so core pins **Kysely
   `~0.28.17`**. Node 20 reached end of life in April 2026. Raising the floor to Node 22
   would remove every hold-back in the table except TypeScript. That is a change to D14 and
   needs an owner decision; nothing here assumes it.

The coverage demonstration found a real defect in my first configuration: with
`coverage.include: ["packages/*/src/**/*.ts"]` the untested file was not counted at all and
the run passed. Vitest resolves `coverage.include` against each project's root, so the
pattern is now `src/**/*.ts`. The demonstration above is from the corrected configuration.

## Decisions

1. **`isolatedDeclarations` is off.** Tried as the spec asks:
   `tsc --noEmit --strict --declaration --isolatedDeclarations docs/plan/spikes/schema-typing.ts`
   reports 16 errors: TS9021 "Extends clause can't contain an expression" on every
   `class X extends Schema(...)`, and TS9012 on every un-annotated `static posts = hasMany(...)`.
   It fights the schema API (D1) directly, and tests and examples export schema classes.
   Recorded in ADR 0001 as well.
2. **TypeScript 6.0.3, not 7.0.2.** With TypeScript 7 installed, `tsc` works but tsup's
   declaration build crashes (`TypeError: Cannot read properties of undefined (reading
   'useCaseSensitiveFileNames')` inside rollup-plugin-dts). The alternative builder, tsdown,
   requires Node >= 22.18. TypeScript 6 satisfies D14 (>= 5.5). tsup injects the deprecated
   `baseUrl` option into its declaration build, which TypeScript 6 reports as TS5101, so
   each `tsup.config.ts` sets `ignoreDeprecations: "6.0"` for the declaration build only.
3. **Kysely `~0.28.17`**, the newest release that supports Node 20 (see "Read this first").
4. **Workspace imports resolve to sources.** `paths` in `tsconfig.base.json` and aliases in
   `vitest.config.ts` map `ectype` and `@ectype/*` to `packages/*/src/index.ts`, so
   `pnpm typecheck` and the tests need no build. Each package has a `tsconfig.build.json`
   (no `paths`, no `composite`, tests excluded) for the tsup declaration build.
   `examples/smoke` and `benchmarks` load the built `dist/`; `pnpm bench` builds first.
5. **`@ectype/test-support` alias** for `packages/core/test/support/index.ts`, so that other
   packages' tests can use the helpers. It is not a package and is never published.
6. **Coverage thresholds are per package through glob keys** (`packages/core/src/**`,
   `packages/postgres/src/**`: 95% lines and branches). Coverage counts `src/` of every
   package, including files no test imports.
7. **"Serial per file" is read as:** integration files run in parallel, tests inside one
   file run serially. This is what acceptance item 5 requires.
8. **`withDatabase` creates a database, not a schema,** named
   `ectype_<label>_<pid>_<12 hex>`, and drops it `WITH (FORCE)`. Besides the callback form
   the spec names, `createTestDatabase` returns a handle for `beforeAll`/`afterAll` use,
   and both accept `{ label, fixtures, settings }`. `Dialect` is `"postgres" | "mysql"`;
   SQLite is left to step 17.
9. **`expectSql` normalisation:** whitespace runs collapse to one space, padding inside
   parentheses and before commas is removed, quoted text is untouched. It accepts a string
   or `{ sql, params? }` and snapshots `{ sql, params }`. If step 02's compiled-query
   contract uses a different field name for parameters, this helper needs a one-line change.
10. **Blog DDL details the spec leaves open.** Columns the spec types explicitly are exactly
    as written (so `tags.name`, `posts.published` and `posts.views` are nullable). Where it
    is silent: timestamps are `timestamptz NOT NULL DEFAULT now()`; `profiles.user_id`,
    `posts.author_id` and `comments.post_id` are `NOT NULL`; `comments.author_id` is
    nullable (a nullable `belongsTo` to test against); `orgs.name` is `text NOT NULL`;
    `memberships.role` is `text NOT NULL DEFAULT 'member'`; `profiles.user_id`, the
    `posts_tags` keys and the `memberships` keys cascade on delete, while `posts.author_id`
    and `comments.author_id` do not (so foreign-key violations can be provoked); indexes
    exist on `posts.author_id`, `comments.post_id` and `comments.author_id`. The fixture is
    PostgreSQL dialect only.
11. **CI uses `docker compose` for the databases** (`pnpm db:up`) instead of a GitHub
    `services:` block, so that image, port, credentials and flags are defined once and the
    acceptance command sequence is what CI runs.
12. **Additions beyond the listed CI jobs:** `integration (tier 2)` (MySQL; the only place
    the MySQL helpers run), a `pnpm smoke` and a `pnpm bench` step in `build+publint+attw`,
    and an aggregate `ci` job meant to be the single required status check.
13. **Biome scope.** `docs/plan/` is excluded from Biome entirely: the plan is frozen,
    `schema-typing.ts` uses `any` by design and `rejected-const-thunks.ts` must not be
    touched. Default exports are allowed only in `*.config.ts` and `docs/site/.vitepress/`;
    non-null assertions only in test files and `test/` directories. `useImportType` and
    `useNodejsImportProtocol` are also errors.
14. **`VERSION` is a literal** in each `src/index.ts`. A unit test in every package asserts
    it equals `package.json`, and `pnpm version-packages` runs `scripts/sync-version.mjs`
    after `changeset version` (verified with a throwaway changeset, then reverted).
15. **Peer dependencies.** `@ectype/postgres`, `@ectype/zod` and the private placeholders
    declare `ectype` as a peer dependency (`workspace:^`); `@ectype/zod` also declares
    `zod ^4.0.0`. Steps 06 and 11 own these packages and may change the ranges.
16. **Benchmark results are git-ignored** (`benchmarks/results/*.json`); step 19 decides
    which results are committed. The report records `gitDirty` because the file is named
    after `HEAD` even when the tree has uncommitted changes.

## Deviations from the spec

- `pnpm db:up` not verified locally (Docker fault, above).
- Kysely is pinned to the newest Node 20 compatible minor, not "the current stable minor".
- CI `integration` uses Compose rather than a `services:` block (decision 11).
- No other intentional deviations. No file under `docs/plan/` was changed except this note.

## Known gaps

- **Changesets and 0.x versions.** With `ectype` as a peer dependency inside a fixed group,
  a `minor` changeset on a 0.x version bumps every package to `1.0.0` (checked: `0.0.0` +
  minor gives `1.0.0`; `1.0.0` + minor gives `1.1.0`). Documented in `.changeset/README.md`.
  Step 21 must settle the pre-1.0 scheme before the first publish.
- **Public packages have no `README.md`.** `publint --strict` does not ask for one; step 21
  should add them before publishing.
- **Docs tooling is a skeleton.** No TypeDoc, Twoslash, link check, spell check, example
  extractor or Pages deployment: step 20 part A. `docs/site/examples/` is type-checked and
  one example is included by reference to show the pattern.
- **Benchmark harness is minimal.** No noise rejection, comparison, seeding, budgets or
  gating: step 19 part A.
- **The parallel pair must run together.** Filtering Vitest down to only one of
  `parallel-a.itest.ts` / `parallel-b.itest.ts` fails after 20 s, by design, with a message
  saying so. It also needs at least two Vitest workers.
- **No declaration maps** (`.d.ts.map`) in the build output; JavaScript source maps only.
