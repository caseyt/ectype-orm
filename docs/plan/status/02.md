### Kysely gaps

Nothing Ecto needs is out of reach. Nine constructs need a raw node or a rewrite; in each
the raw text is a constant of the lowering code:

- **Raw glue:** window frames (`ROWS BETWEEN …`); `PARTITION BY` an expression; a `VALUES`
  source with a column alias list; `TABLESAMPLE`; lock clauses outside the standard modes.
- **One keyword from a raw node:** JSON `#>` / `#>>`; `CAST` to a type Kysely does not
  list; `EXPLAIN` options.
- **Rewritten:** named windows (`WINDOW w AS …`) are expanded at each use, because
  Kysely's select node has no `WINDOW` clause.

Also found: Kysely's compiler adds no parentheses (precedence is the lowering's job);
function names, operators and data types are appended unquoted (so they must come from the
lowering's tables); a selected bare parameter must be cast (a Postgres rule, not a Kysely
one); Kysely 0.29 is ESM-only. Besides the nine constructs, the lowering supplies `asc` and
`desc` as constant raw nodes, because Kysely takes the sort direction as a node.

## Decisions

Decisions marked **(round 1)** were made or changed in response to the first review.

1. **Public exports.** `src/index.ts` exports the error classes, `isEctypeError`,
   `Result`, `ok` and `err`, and nothing else from this step. Contract types become public
   through the step that implements them. `index.test.ts` pins the list of runtime exports.
   A changeset (`.changeset/step-02-core-contracts.md`, minor) records it.
2. **Error codes** are lower-case snake strings (`"no_results"`, `"stale_entry"`, …).
   `AdapterError` has several (`"adapter"`, `"connection"`, `"serialization_failure"`,
   `"deadlock"`, `"aborted"`, `"timeout"`), because step 11's spec assigns those to `code`;
   `retryable` defaults to true for the two conflict codes. `ConstraintError` exposes the
   constraint's name as `constraint`, not `name` as the step file says: an `Error` already
   has a `name`. Its type includes `"notNull"` (step 11 maps SQLSTATE 23502 to it), and the
   database's detail line is kept as `detail` but out of `message`, because it can quote
   row values. `InvalidChangesetError` lists the errors by field and never a value.
3. **`META`, `ROW` and the error brand are `Symbol.for(…)`**, and `isEctypeError` tests the
   brand, not `instanceof`, so that two installed copies of the package agree. `IDENTITY`
   cannot be shared that way (it is a function): a type from another copy is still correct
   and only misses the skip-the-call shortcut.
4. **No `any` in the contracts.** Where the step file writes `EctoType<any, any>`, the
   contract has `AnyEctoType = EctoType<unknown, unknown>`. It works because `EctoType`
   declares its members with method syntax (parameters are then bivariant). `AnySchema`
   uses `never[]` and `object`. **(round 1)** `Row<S>` is a conditional type, not
   `InstanceType<S>`: with `never[]` constructor arguments `InstanceType` fell through to
   `any`, so `Row<AnySchema>` was `any`. It is `object` now, and a type test asserts
   `not.toBeAny()` for every schema-derived type applied to `AnySchema`.
5. **The type-level schema contract** (lifted from the spike, then extended):
   - `FieldBuilder<T, F>` carries `T` (including `| null` after `.nullable()`) and four
     flags: `nullable`, `defaulted` (set by `default`, `autogenerate` and
     `readAfterWrites`), `virtual`, `primaryKey`. It declares all nine modifiers.
   - A schema class has two reserved statics: `[META]` and `fields`.
   - `Assoc<Kind, Target, FK>` has a third parameter, the foreign-key field name when it
     was given as a literal. `Loaded` uses it to make a preloaded `belongsTo` non-null
     exactly when the foreign-key field is non-null (default name `<assoc>Id`); when the
     key cannot be determined the result is `| null`.
   - `Loaded<S, P>` accepts a key, a union, a nested object (values: a nested spec or
     `true`), and arrays. An unknown association is a compile error at every depth.
   - **(round 1)** `ValidPreload<S, P>` and `LoadedUnchecked<S, P>` are how a *generic
     function* takes a spec: `spec: P & ValidPreload<S, P>` rejects a stray key beside a
     valid one, which `P extends PreloadSpec<S>` does not (TypeScript checks excess
     properties only against a non-generic target). Type tests cover the string, nested
     object and array forms, positive and negative.
   - `PrimaryKeyOf<S>` (scalar, object for a composite key, `never` without one) is added
     for `repo.get` (step 12).
   - `AssocMeta` keys are arrays of field names (composite keys); embeds are listed in
     `SchemaMeta.fields` **and** in `embeds`; `RowMeta.source` is `string | null` (rows of
     embedded schemas have no table).
   - **(round 1)** `SchemaMeta.create(values, row)` takes the row's `RowMeta`;
     `rowMeta(state, prefix)` returns the shared one for the prefix the statement ran in;
     `createWith(assocs)` is the row factory for rows that carry preloaded associations
     (step 14, one hidden class per association list).
6. **Parameter order and `shape` are canonical** (accepted by the owner, decision D).
   `QueryAst.params` is the values of the query's parameter nodes in a depth-first walk in
   interface declaration order, with the invariant `ast.params` equals
   `collectParams(ast)`. An AST does not record the order in which clauses were appended,
   so "clause-append order" could not be numbered by a compiler. **(round 1)** The
   contract now also says: `shape` is canonical too (structure only, whatever the build
   order), so two structurally identical queries share one plan, which is what step 10's
   cache assumes; what contributes to it is listed (literal values and preload names do,
   parameter values, list lengths and select constants do not); and the **builder** keeps
   the per-property param counts, list counts and hashes outside the AST, which is what
   keeps adding a clause O(size of the clause). Steps 07, 08 and 10 were edited to agree.
7. **The query AST is defined in full here** (20 expression kinds and 18 other kinds), from
   the lists in the step 02 and step 07 files. The top level of `QueryAst`, the clause
   nodes, the node rules, the parameter order and `shape` are frozen. The fields of
   individual expression nodes may be refined by step 07 until it merges. Added beyond the
   lists: `ident`, `kind: "query"`, `params`. Not defined: a `between` node. `hints` are
   fragments. **(round 1)** Added: `listLengths` (the plan-cache key on dialects that
   expand lists); `SelectNode.constants` and a `constant` leaf (a selected plain value is
   returned as it is, never sent to the database, and stays out of the shared plan);
   `CteNode.operation` (data-modifying CTEs); `cteSource` (a CTE reference is not a table:
   no prefix applies); `redact` on parameter nodes.
8. **Adapter contract.**
   - `ParamSlot` has four kinds (`inline`, `list`, `element`, `named`) and carries `dump`
     (`undefined` means identity) and **(round 1)** `redact`.
   - `CompiledQuery` has `output` next to `decoder`, and **(round 1)** `prefix`.
   - `execute` and `stream` take no connection argument: `Adapter` and `Connection` both
     extend `Executor`.
   - `typeOverrides` is a function `(type) => Codec | undefined`, **(round 1)** documented
     as cached per adapter instance, not per dialect.
   - `Capabilities` is spelled out (20 members).
   - `on(event, listener)` with `query`, `connect`, `disconnect`, `poolExhausted`.
   - **(round 1) Prefix.** `compile`, `compileExplain`, `compileInsert`, `compileUpdate`
     and `compileDelete` take the weakest prefix (per-call, else repo default). Resolution
     order for a table, **(round 2)** now exactly Ecto's: the source's prefix, the schema's
     declared prefix, the query's, the argument. Row-level writes: the argument, else the
     schema's. **(round 3)** For every row-level write, insert included, the repo passes
     the per-call option, else the row's `RowMeta.prefix`, else its default; a built row
     holds its schema's declared prefix. The contract has the table of cases (schema
     prefix only, repo default only, both) showing that insert, get/all, update and delete
     land on the same table. `OutputPlan`'s `nullable` test for a keyless schema is "every
     column is null". The repo never rewrites
     an AST to apply a prefix; the prefix is part of the plan-cache key; the plan reports
     the prefix its root table resolved to and the repo stamps it on the rows.
   - **(round 1) Inserts.** `compileInsert` takes an `InsertSource`: uniform bound values;
     cells (`value`, `default`, `expr`, `placeholder`); or a query (`INSERT … SELECT`). The
     layout of the parameter array is specified in three sections: the source, a
     conflict-target fragment, a conflict-action query.
   - **(round 1)** `compileFragment` (what `repo.query` runs), `compileExplain`,
     `RawResult.insertId`, `Connection.destroy`, `ExecuteOptions.slots` (so the adapter can
     mask redacted parameters in events), `ExecuteOptions.context` (returned on the event,
     to match an event to its call) and `ExecuteOptions.statementName`.
   - **(round 1)** `OutputPlan`: a `constant` leaf; the `row` leaf has `nullable` (absent
     side of an outer join) and `preloads`. `RowDecoder` takes the query's constants as a
     second argument.
   - **(round 2)** A `RowDecoder` is stateless and per row. For a join preload it builds
     the parent with that row's child in place; the repo's post-decode stage (step 12's
     `afterDecode`) merges parents by primary key. The `row` leaf has `key` (the output
     columns of the primary key), and `preloads` lists every preload of the row, with
     `row: undefined` for one loaded by a separate query.
9. **(round 1) `ValidatorFn` returns `void`** when it has nothing to report, as step 06
   specifies (owner decision C). The first version used `undefined` to satisfy Biome's
   `noConfusingVoidType`; the review showed that this rejected ordinary validators. Type
   tests now cover: an inline function with and without a return, sync and async; a named
   function with no `return`; a function annotated `: void`; an `async` function typed
   `Promise<void>`; an arrow whose body is a call to a void function; and a body that
   returns issues on some paths only. One correction to the review's list: under
   `noImplicitReturns`, an **unannotated** inline function that returns on some paths is
   TS7030 with either type; what `void` buys there is that the same body annotated
   `: ValidatorResult` compiles (checked by hand with the flag; the repository does not
   enable it).
10. **Standard Schema types use flat names** (`StandardSchemaV1Issue`) instead of the
    specification's namespace. Structurally identical.
11. **`internal/`.**
    - `hash.ts`: FNV-1a, 32-bit, results kept as signed integers. `hashString` mixes the
      length first, then two bytes per UTF-16 code unit.
    - `lru.ts`: a `Map` plus a doubly linked list (the first version, a `Map` in insertion
      order, measured 60 ns to 1.3 µs per hit; the benchmark keeps it as a baseline).
    - `naming.ts`: the rules of Elixir's `Macro.underscore`; memoised, the memo emptied at
      4,096 entries.
    - `inspect.ts`: its own formatter, without `node:util`. **(round 1)** It runs no code
      of the value: built-in methods are called from their prototypes, and an accessor
      shows as `[Getter]` instead of being read. A row of a schema hides its redacted
      fields at any depth (found through the class's `META`); a *plain object* of field
      values is not recognised, and the documentation says so. **(round 2)** It fails
      closed: if `META`, `fields` or a field's `name` or `redact` is not an own data
      property of the expected type, every value of that row is redacted. The contract now
      requires those to be own data properties. **(round 3)** The schema class is looked
      for along the whole prototype chain (a deleted or accessor `constructor`, or an extra
      prototype layer, no longer hides it), and an object that carries the `ROW` marker but
      has no findable schema has every value redacted. `redactFields` and
      `omitRedacted` keep an own `__proto__` key as an own key.
12. **Benchmarks of internal code load `dist/internal.js`**, a second build entry that is
    not in the package's `exports`. **(round 1)** It is also excluded from the published
    files (`"!dist/internal.*"`); the benchmarks load it from the workspace.
    `pnpm pack --dry-run` lists `dist/index.js`, `dist/index.d.ts` and the source map.
13. **The spike is a private workspace package** (`@ectype/spike-kysely-bridge`). No new
    dependency version. The root `tsconfig.json` references it. It is not run by CI (owner
    decision E). **(round 1)** Running it no longer changes a committed file: the benchmark
    writes to a git-ignored file unless `SPIKE_COST_RECORD=1`.
14. **No deep-equality helper.** Step 03 adds it (see Requests).
15. **(round 1) ESM only, Node >= 22.12** (owner decision B). No CommonJS build: tsup emits
    ESM, and `exports` has `types` and `default` (no `require` condition, and `default`
    rather than `import` so that `require()` resolves it). The floor was measured with
    real Node binaries: 22.11.0 fails with `ERR_REQUIRE_ESM`, 22.12.0 works with an
    `ExperimentalWarning`, 22.23.1 and 24.14.1 work silently. `engines.node` is `>=22.12`
    in the root and in all six packages (it was `>=22`). `examples/smoke/require-esm.cjs`
    replaces the CommonJS consumer: it `require()`s the three packages, and checks that
    what it got is the same module instance an `import` gets.
16. **(round 1) `attw` runs with `--profile esm-only`.** That profile ignores exactly two
    of attw's four resolution modes, `node10` and `node16-cjs` (they are still printed,
    marked "ignored"), because a package without a CommonJS build cannot satisfy them:
    attw's rule there is "a `require` call resolved to an ESM file", which is precisely
    what the package intends on Node >= 22.12. The `node16` ESM mode and the `bundler` mode
    must be clean, and are. `publint --strict` is unchanged and passes.
17. **(round 1) `DbType`'s `custom.sql` is trusted input**, the third and last source of raw
    SQL text (ADR 0002, rule 2). It must come from developer-written type definitions,
    never from user data, and the compiler emits it only if it matches the exported
    `CUSTOM_SQL_TYPE` pattern (a plain type name).

## What went wrong along the way

1. **A spike script crashed once after printing its last check**, with an unhandled
   `error` event on a `pg` client that was being closed while `DROP DATABASE … WITH (FORCE)`
   ran. I did not capture the message. The helper now waits for the database's backends to
   exit before dropping it, and the crash has not recurred in the roughly 60 script runs
   since. The cause is an inference from the dumped client state, not something I
   reproduced on purpose.
2. **The first quick run of the cost script reported +6.8% overhead** for the one-row
   case, from 4 rounds of 200 calls. Four full runs since gave medians between −0.70% and
   +1.06%.
3. **The first `LruCache` was slow**; found by its own benchmark.
4. **A `hashInt` benchmark measured a constant** (the JIT folded the call). It now takes a
   changing input.
5. **`ADR 0002` first said 18 gap cases were compared row for row; the output says 13.**
   Corrected before the first commit of the ADR.
6. **The first version of the contracts could not support five specified features**
   (review findings 1 to 5). I had judged sufficiency by reading the "Public API" sections
   and missed behaviour items further down (prefix precedence, the read-back insert path,
   `insertAll`'s forms, `repo.query`, literals in a select). In round 1 I re-read the
   Behaviour sections as well and wrote a fake of each consuming feature against the
   contract.
7. **The first status note said a stray preload key "is rejected in value position".**
   True for an annotated variable, false for a generic function, which is what `preload()`
   is. Corrected by the `ValidPreload` helper and its tests.
8. **A commit in round 1 briefly contained only a file rename** under the full ESM-only
   message, because `git add` had failed on a path that no longer existed and I committed
   without re-reading the staged list. It had not been pushed; I amended it locally to
   contain the whole change (`e475cf9`). Nothing was force-pushed.
9. **My first smoke check asserted that an ES module is absent from `require.cache`.** It
   is present. The assertion was removed; the claim it stood for was never in the docs.
10. **Three things I added in round 1 were wrong and were caught in round 2.** The output
    plan's text gave the per-row decoder a job (de-duplicating parents) it cannot do. The
    prefix order put a schema's declared prefix last, where Ecto puts it second; I had
    reasoned from step 10's three-item list without checking Ecto's documentation. And
    the nested redaction returned "nothing redacted" whenever it could not read the
    metadata, which is the unsafe default.
11. **The round 2 prefix rule still left insert out.** I had written "for an update or
    delete, the row's prefix" and did not walk an insert through the same cases. Round 3
    added the table that would have shown it.

## Known gaps and unverified claims

- **The contracts are still proven by fakes, not by implementations.** The fakes are now
  written per consuming feature (`adapter.test-d.ts`, "what steps 08 to 17 need"), but
  they are type-level: nothing executes them.
- **The `?` dialects were compiled, not executed.** No MySQL or SQLite database was
  involved in the spike.
- **Not exercised in the spike:** streaming, cancellation, Kysely's MySQL and SQLite
  drivers, and whether those drivers read `CompiledQuery.query`.
- **Canonical numbering is verified for the node kinds of the spike's AST**, not for the
  contract's full node set.
- **Spike features not run individually** (same node, another enum value): `FOR SHARE`,
  right joins, `INNER JOIN LATERAL`, `<@`, `INTERSECT`, `UNION` without `ALL`,
  `NULLS FIRST`, `RANGE` frames.
- **The cost numbers come from one machine,** with Postgres behind a VM boundary.
- **The Node floor** was tested on 22.11.0, 22.12.0, 22.23.1 and 24.14.1 (macOS arm64).
  Which 22.x release first loads an ES module with `require` *without* a warning was not
  determined. The two older binaries were downloaded from nodejs.org into `/tmp` for this
  check and are not part of the repository.
- **`CUSTOM_SQL_TYPE` is a pattern in the contract; nothing enforces it yet.** Step 10's
  compiler must apply it. The contract test checks what the pattern accepts and rejects.
- **Redaction of a plain object** that holds field values (a changeset's `changes`) is the
  caller's job; `formatValue` cannot recognise it. Step 05 must use `formatStruct` with the
  schema's redacted names.
- **TSDoc examples are not type-checked.** The extractor is step 20's.
- **Zod against the vendored Standard Schema types** was checked by hand in round 0 (a
  scratch type test with Zod 4.6.5), then deleted. Nothing in the repository asserts it.
- **`noImplicitReturns` behaviour of `ValidatorFn`** was checked by hand; the repository
  does not enable the flag, so no committed test runs under it.
- **Compile-time cost of the types** on large schemas was not measured.
- **MySQL (tier 2) integration tests were not run locally**; CI runs them.
