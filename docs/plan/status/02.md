### Kysely gaps

Nothing Ecto needs is out of reach. Nine constructs need a raw node or a rewrite; in each
the raw text is a constant of the lowering code:

- **Raw glue:** window frames (`ROWS BETWEEN …`); `PARTITION BY` an expression; a `VALUES`
  source with a column alias list; `TABLESAMPLE`; lock clauses outside the standard modes.
- **One keyword from a raw node:** JSON `#>` / `#>>`; `CAST` to a type Kysely does not
  list; `EXPLAIN` options.
- **Rewritten:** named windows (`WINDOW w AS …`) are expanded at each use, because
  Kysely's select node has no `WINDOW` clause.

Also found: Kysely's compiler adds no parentheses (precedence is the lowering's job);
function names, operators and data types are appended unquoted (so they must come from the
lowering's tables); a selected bare parameter must be cast (a Postgres rule, not a Kysely
one); Kysely 0.29 is ESM-only.

## Decisions

1. **Public exports.** `src/index.ts` now exports the error classes, `isEctypeError`,
   `Result`, `ok` and `err`, and nothing else from this step. Contract types become public
   through the step that implements them. `index.test.ts` pins the list of runtime exports.
   A changeset (`.changeset/step-02-core-contracts.md`, minor) records it.
2. **Error codes** are lower-case snake strings (`"no_results"`, `"stale_entry"`, …).
   `AdapterError` has several (`"adapter"`, `"connection"`, `"serialization_failure"`,
   `"deadlock"`, `"aborted"`, `"timeout"`), because step 11's spec assigns those to `code`;
   `retryable` defaults to true for the two conflict codes. `ConstraintError` exposes the
   constraint's name as `constraint`, not `name` as the step file says: an `Error` already
   has a `name`. Its type includes `"notNull"` (step 11 maps SQLSTATE 23502 to it), and the
   database's detail line is kept as `detail` but out of `message`, because it can quote
   row values. `InvalidChangesetError` lists the errors by field and never a value.
3. **`META`, `ROW` and the error brand are `Symbol.for(…)`**, and `isEctypeError` tests the
   brand, not `instanceof`: the package ships ESM and CommonJS builds, and one process can
   load both.
4. **No `any` in the contracts.** Where the step file writes `EctoType<any, any>`, the
   contract has `AnyEctoType = EctoType<unknown, unknown>`. It works because `EctoType`
   declares its members with method syntax (parameters are then bivariant); a type test
   proves that every `EctoType<A, D>` is assignable to it. `AnySchema` likewise uses
   `never[]` and `object`.
5. **The type-level schema contract** (lifted from the spike, then extended):
   - `FieldBuilder<T, F>` carries `T` (including `| null` after `.nullable()`) and four
     flags: `nullable`, `defaulted` (set by `default`, `autogenerate` and
     `readAfterWrites`), `virtual`, `primaryKey`. It declares all nine modifiers.
   - A schema class has two reserved statics: `[META]` and `fields`.
   - `Assoc<Kind, Target, FK>` has a third parameter, the foreign-key field name when it
     was given as a literal. `Loaded` uses it to make a preloaded `belongsTo` non-null
     exactly when the foreign-key field is non-null (default name `<assoc>Id`); when the
     key cannot be determined the result is `| null`.
   - `Loaded<S, P>` accepts a key, a union, a nested object (values: a nested spec or
     `true`), and arrays. An unknown association is a compile error at every depth.
   - `PrimaryKeyOf<S>` (scalar, object for a composite key, `never` without one) is added
     for `repo.get` (step 12).
   - `AssocMeta` keys are arrays of field names (composite keys); embeds are listed in
     `SchemaMeta.fields` **and** in `embeds`; `RowMeta.source` is `string | null` (rows of
     embedded schemas have no table).
6. **Parameter order is canonical, not clause-append order.** `QueryAst.params` is defined
   as the values of the query's parameter nodes in a depth-first walk in interface
   declaration order, with the invariant `ast.params` equals `collectParams(ast)`. Step
   10's spec says "clause-append order", but an AST does not record the order in which
   clauses were appended, so the compiler could not number the parameters it meets, and two
   queries of the same shape built in different orders would lay out `params` differently
   while sharing a plan. A canonical order is also what Ecto's planner does. Cost: a builder
   that adds a clause "out of order" (a `where` after a `limit`) inserts into the middle of
   a small array instead of appending.
7. **The query AST is defined in full here** (20 expression kinds and 17 other kinds), from
   the lists in the step 02 and step 07 files. The top level of `QueryAst`, the node rules
   and the parameter order are frozen. The fields of individual expression nodes may be
   refined by step 07 until it merges (it is their first consumer); `contracts/README.md`
   says so. Added beyond the lists: `ident` (for `fragment.ident`), `kind: "query"` on
   `QueryAst`, `params`. Not defined: a `between` node. `hints` are fragments (decision D9
   allows raw text only through `fragment`).
8. **Adapter contract refinements.**
   - `ParamSlot` has four kinds (`inline`, `list`, `element`, `named`) and carries `dump`
     (`undefined` means identity). `list` and `element` are what arrays need on Postgres
     and on the `?` dialects.
   - `CompiledQuery` has `output` (the `OutputPlan` that step 10 describes) next to
     `decoder`; `decoder` is the one mutable member.
   - `execute` and `stream` take no connection argument. `Adapter` and `Connection` both
     extend `Executor`, so repo code written against `Executor` runs on either.
   - `typeOverrides` is a function `(type) => Codec | undefined`. A map by column kind
     would not let Postgres treat `id` (bigint column, `number` in the app) differently
     from `bigint`.
   - `Capabilities` is spelled out (20 members): the step file's list plus
     `conflictTarget`, `distinctOn`, `arrayParams`, `nullsOrder`, `updateJoin`,
     `isolationLevels`, `stream`, `maxParams`, taken from the table in step 17.
   - `on(event, listener)` with `query`, `connect`, `disconnect`, `poolExhausted`, because
     the repo forwards telemetry through the interface (step 12).
   - `compileInsert`, `compileUpdate` and `compileDelete` take `FieldMeta` lists, and the
     layout of the values array their slots index is specified.
9. **`ValidatorFn` returns `undefined`, not `void`,** when it has nothing to report. Step
   06 writes `ValidationIssue[] | void`; Biome's `noConfusingVoidType` (part of the
   recommended set, and warnings fail `pnpm lint`) rejects `void` in a union, and I did not
   disable the rule. Inline functions are unaffected (a function with no `return` is
   accepted, sync or async; type tests cover it). What is lost: a named function annotated
   `: void` is not assignable, and under `noImplicitReturns` a body that returns issues on
   some paths needs an explicit `return;` on the others.
10. **Standard Schema types use flat names** (`StandardSchemaV1Issue`) instead of the
    specification's namespace. Structurally identical.
11. **`internal/`.**
    - `hash.ts`: FNV-1a, 32-bit, results kept as signed integers. `hashString` mixes the
      length first, then two bytes per UTF-16 code unit.
    - `lru.ts`: a `Map` plus a doubly linked list. My first version kept order with the
      `Map`'s insertion order; the benchmark showed 62 ns per hit and 1.1 µs when one key is
      hit repeatedly, so it was replaced (commit `fbedbe6`). The benchmark keeps the old
      design as a baseline.
    - `naming.ts`: the rules of Elixir's `Macro.underscore`; memoised, the memo emptied at
      4,096 entries. The round trip holds only for conventional names; the exceptions
      (`userID`, `address2Line`, `aBC`) are documented and tested.
    - `inspect.ts`: its own formatter, without `node:util`; never calls a `toString` or
      `toJSON` of the value; does not read the value of a redacted field.
12. **Benchmarks of internal code load `dist/internal.js`.** The utilities are not public,
    so `packages/core/tsup.config.ts` has a second entry that is **not** in the package's
    `exports` (`import "ectype/internal"` fails with `ERR_PACKAGE_PATH_NOT_EXPORTED`,
    checked for ESM and CommonJS). The alternative was to import the sources, which is what
    step 01's review rejected for benchmarks.
13. **The spike is a private workspace package** (`@ectype/spike-kysely-bridge`), so that
    its scripts resolve `kysely`, `pg` and `mitata`. No new dependency version: the lockfile
    gained one importer block. The root `tsconfig.json` references it, so `pnpm typecheck`
    covers it.
14. **No deep-equality helper.** Step 03's spec puts one in `internal/`; it is not needed
    to freeze an interface, so step 03 adds it (see Requests).

## What went wrong along the way

1. **A spike script crashed once after printing its last check.** `02-param-slots.ts`
   ended with an unhandled `error` event on a `pg` client that was being closed while
   `DROP DATABASE … WITH (FORCE)` ran. I did not capture the message. The helper now waits
   for the database's backends to exit before dropping it, and the crash has not recurred
   in the roughly 25 script runs since. The cause is an inference from the dumped client state
   (`_ending: true`), not something I reproduced on purpose.
2. **The first quick run of the cost script reported +6.8% overhead** for the one-row
   case. It was 4 rounds of 200 calls. Three full runs (40 rounds of 1,500 calls) gave
   medians between −0.70% and +1.06%, so I treat the first figure as noise; it is why the
   quick mode writes to a separate, git-ignored file.
3. **The first `LruCache` was slow** (decision 11); found by its own benchmark.
4. **A `hashInt` benchmark measured a constant** (0.4 ns: the JIT folded the call). It now
   takes a changing input.
5. **`ADR 0002` first said 18 gap cases were compared row for row; the output says 13.**
   Corrected before the commit.

## Known gaps and unverified claims

- **The contracts are proven by fakes, not by implementations.** The type tests build a
  fake schema API, a fake adapter and a hand-written AST. Whether the contracts are
  sufficient for steps 03 to 18 is a judgement from reading their "Public API" sections.
- **The `?` dialects were compiled, not executed.** No MySQL or SQLite database was
  involved in the spike.
- **Not exercised in the spike:** streaming, cancellation, Kysely's MySQL and SQLite
  drivers, and whether those drivers read `CompiledQuery.query`.
- **Spike features not run individually** (same node, another enum value): `FOR SHARE`,
  right joins, `INNER JOIN LATERAL`, `<@`, `INTERSECT`, `UNION` without `ALL`,
  `NULLS FIRST`, `RANGE` frames.
- **The cost numbers come from one machine,** with Postgres behind a VM boundary (340 µs
  per round trip). The spike's lowering covers a subset of node kinds, so step 10's cold
  compile will cost more than 5.70 µs.
- **`Loaded` with a stray key.** In a type argument, an unknown key beside a valid one
  (`Loaded<typeof User, { posts: true; nope: true }>`) is ignored, not rejected. In value
  position (what `preload()` takes) it is rejected. A type test documents both.
- **TSDoc examples are not type-checked.** The extractor is step 20's. They were written
  with care but nothing compiles them.
- **Zod against the vendored Standard Schema types** was checked by hand (a scratch type
  test in `packages/zod` with Zod 4.6.5, including the two Zod examples of step 06), then
  deleted. Nothing in the repository asserts it.
- **Compile-time cost of the types** on large schemas was not measured.
- **"Node before 22.12 cannot `require` an ES module"** in the ADR is from memory.
  `require("kysely")` was checked on 22.23.1 and 24.14.1 only.
- **`dist/internal.*` ships in the npm tarball** although nothing can import it.
- **MySQL (tier 2) integration tests were not run locally** for this step.
