## Decisions

1. **The root alias is a fourth type parameter**: `Query<B, R, P, A>`. The object form of
   `where`, `preload` and `exclude("select")` need the root binding's schema; `B` alone
   does not say which binding is the root, and an extra key in `B` would show up in every
   callback's destructuring. `QueryWith` leaves it as `string` (any root).
2. **Methods that keep the bindings return `this`** (`where`, `orWhere`, `having`,
   `orderBy`, `groupBy`, `distinct`, `limit`, `offset`, `lock`, `schema`,
   `reverseOrder`): exactly the receiver's type when the clause adds no named parameter,
   so a scope `<Q extends QueryWith<…>>(q: Q) => q.where(…)` returns `Q` and keeps its
   result type and parameters (behaviour 10). With named parameters the result is `Q`
   with them added (`AddParams`). `select`, `selectMerge` and `preload` take the receiver
   as a `this` type parameter for the same reason, and because writing their result in
   terms of the class's own parameters made the compiler's comparison of two query types
   recurse without end through the declaration files (TS2589 in the docs examples).
3. **Clause callbacks** are constrained with `Expr<boolean | null, SomeParams>` and
   infer their concrete result `X`; `P` merges `ParamsOf<X>`; at run time `joinNamed`
   refuses one name with two types in every clause (step 07 requests). (Until review
   round 2 the callback's result was also intersected with `Compatible<P, X>`; decision
   30 removed that.)
4. **`QueryWith<Bs>`** maps each alias to `Binding<S, boolean>`, so a scope accepts a
   joined and a left-joined binding alike; `QueryWith` with no argument is any query.
   **`hasNamedBinding(q, alias, Schema?)`** takes an optional schema class (an addition to
   the step file): with it, the narrowed binding is typed by that schema; without it the
   binding's columns are unknown. Explicit beats inferred here.
5. **Where-object form**: keys are the root binding's columns and values are typed by the
   field (`null` only on nullable fields, arrays for `IN`); `undefined` throws with the
   conditional-composition hint; a field without a column (virtual, unknown) throws
   listing the columns. An **empty object is `TRUE`** (a filter built from data may be
   empty). `orWhere` takes the object
   form too.
6. **A query has one `select` and one `distinct`**: a second call throws (use
   `selectMerge`, or `exclude("select")` first).
   `limit`, `offset`, `lock` and `schema` replace an earlier call; `where`, `groupBy`,
   `having`, `orderBy` and joins append.
7. **`selectMerge` needs an object select** (behaviour 8), and with none it throws rather
   than merging into the whole row. A key present on both sides takes the new value in the
   old position.
8. **`having` needs a `groupBy` before it** (behaviour 8). It takes a callback only.
9. **Removing a named parameter throws.** `exclude(clause)`, replacing a `limit` /
   `offset` / `lock`, and a `selectMerge` key that replaces one would drop a named
   parameter from the query while its type still requires it (the compiler of step 10
   refuses extra parameters). The builder refuses instead, naming the parameter.
10. **`exclude`** removes `where` (with `orWhere`), `select`, `distinct`, `groupBy`,
    `having`, `orderBy`, `limit`, `offset`, `lock` or `preload`. Not `join`: the
    conditions that use a joined binding would stay behind. `exclude("select")` types the
    result as the root row again; `exclude("preload")` as the root row when the result was one.
11. **`reverseOrder`** swaps `ASC`/`DESC` and `NULLS FIRST`/`NULLS LAST`; with no order it
    orders by the root's primary key, descending, and
    throws when there is none.
12. **Locks**: the four modes become the upper-case clauses of `Capabilities.lockModes`
    (`"FOR UPDATE"`, `"FOR NO KEY UPDATE"`, …), with `" SKIP LOCKED"` or `" NOWAIT"`
    appended, from a table in the builder (no caller text). Both options at once throw.
    `lock(fragment\`…\`)` stores the fragment; another expression throws.
13. **`limit` / `offset`** take a safe non-negative integer (bound with `t.integer()`'s
    type) or an expression (a `param(...)`); other values throw naming the value's kind.
14. **Aliases**: a non-empty string not starting with `$`. `$` names are the builder's
    own: a many-to-many join table is `$<alias>_join`, a step of a `through` chain
    `$<alias>_<i>_<assoc>`. Callbacks never see them; `hasBinding` and `hasNamedBinding`
    say `false` for them.
15. **`joinAssoc`** writes `target.relatedKey[i] = owner.ownerKey[i]` (one flat `AND` for
    composite keys), ANDs the association's `where` (bound values) into the `ON`, and for a
    many-to-many two joins: `jt.<owner column> = owner.<key> AND <joinWhere>`, then
    `target.<key> = jt.<target column> AND <where>`. Join-table columns are typed by the
    join schema's field, or by the field they point at. A `through` association becomes the
    chain of its steps (the schema step refuses `where` on it). The fourth argument is ANDed
    into the last `ON`. A `leftJoinAssoc` makes every join of the chain a left join.
16. **Preloads**: specs are validated against the association metadata at build time,
    at every depth. Several `preload` calls merge into one node per association; two
    callbacks for one association, or one association loaded from two sources (a binding
    and a separate query), throw. The callback form runs the callback once on
    `from(Target, name)`, requires the returned query to be rooted there, stores its AST
    in `PreloadNode.query` and its preloads in `nested`, and checks at build time that a
    `limit`/`offset` has an order (the callback's or the association's `orderBy`) and that
    a select keeps the association's key under its field name, as a column of that field
    (many-to-many and `through` are exempt). The join form `{ posts: "p" }` /
    `{ posts: { $from: "p", … } }` is taken only for a binding joined from the parent
    binding through that association, otherwise the string is a nested association. Its
    type (`ValidSpec`, `NormalizeSpec`) accepts an alias whose binding is of the target
    schema; the stricter "joined through that association" is a run-time check.
    A preload requires the select to be the root row, in either order of the calls.
    A preload callback's named parameters are part of `P` (`namedParams()` lists them);
    they are not in the outer AST's `named`, since its query is a separate statement.
17. **Subqueries**: `[AS_SUBQUERY]()` returns an `Expr` of the subquery node, typed by the
    single selected expression (`undefined` otherwise), with the query's params, lists,
    named parameters (canonical order) and `shapeOfSubquery`. A query with preloads
    cannot be a subquery (`QueryError`).
18. **Sources for step 09**: `from` and the joins take a schema class or any object with
    an `[AS_SOURCE](alias)` method returning `SourceParts` (node, binding, meta, params,
    lists, named). A bare `Query` is refused at compile time and with a `QueryError` that
    points at `subquery(q)`. The binding of a source is registered with `registerBinding`
    when it can be selected whole.
19. **Canonical params and shape**: the query keeps, per top-level AST property, a param
    count, a list count and a hash; a clause's params are spliced at the offset the counts
    give; `shape` is `combineQueryShape` of the per-property hashes. Clause hashes are
    built from the expressions' own shapes with the seeds `shapeOf` uses (`bool`, `join`,
    `distinct`, `lock`), so nothing already hashed is walked again; tests check
    `ast.shape === shapeOf(ast)`, `ast.params` / `listLengths` / `named` against
    `collectParams(ast)` on every built query, and a property test (500 runs) that
    random clause orders give equal shapes and params.
20. **Immutability is enforced by the tests**, not by a dev-mode freeze in the library:
    contract rule 2 says nodes are frozen by convention because `Object.freeze` costs
    time on every node. The tests deep-freeze built queries and derive from them.
21. **`from(Schema, alias)` returns one cached query per (schema, alias)** (immutable, so
    shared safely); bindings are cached in a `WeakMap` keyed by the schema's metadata
    object rather than as a property on it, which would change the metadata's shape.
22. **`toString()`** renders without values (`?` for a value, `:name` for a named
    parameter), so nothing redacted can appear; `util.inspect` prints `Query<…>`.
23. **Callback errors**: a `QueryError` thrown inside a clause callback is re-raised as
    `<clause>(): <message>` with the original as `cause`; one that already starts with
    the clause (from a nested query) is passed through. Other errors pass through unchanged.
24. **The object form compares an array or JSON column with a whole value** (review round
    1, owner decision): the guide promises `IN` for an array, which stays for scalar
    columns; on a column of kind `array`, `json` or `jsonb` an array is the value, compared
    with `=` and the column's type. In the types, a field whose value is an array or an
    object (array, JSON, embed) takes a whole value only. The callback form (`.in()`,
    `.contains()`, …) covers the rest.
25. **A right or full join types the rows of a query with no select as `Row | null`**, and
    must come before the query's `select` and `preload` (a `QueryError` otherwise): both
    take the rows as they are when added, and a select made before the join would keep
    non-null types. A preload on a query with a right or full join is refused too, since
    a preload needs root rows that exist. (Review round 1.)
26. **A preload callback's named parameters share the query's names** (review round 1): one
    name with two types is refused at run time (`joinNamed` against the query's names when
    the preload is added, and against the preloads' names whenever a later clause adds one)
    and, since decision 30, gives the query a `never` parameter at compile time.
27. **Scopes** (review round 1): the joins, `exclude`, `select`, `selectMerge` and
    `preload` take the receiver as a `this` type parameter and write their result from its
    `"~query"`, so a scope that joins, excludes or selects keeps `R` and `P`; their
    arguments are checked against the class's own `B`, which the scope's constraint
    resolves. `AddParams` reads `"~query"` too, which removed the TS2589 that
    `hasNamedBinding`'s intersection type caused.
28. **`select(({ u }) => u)` and `exclude("select")` keep what is preloaded** (review round
    1): a select of the whole root binding keeps the query's result type, and `exclude("select")`
    keeps a result that is the root row.
29. **`exclude("groupBy")` with a `having` throws**, naming `exclude("having")` as the first
    step (review round 1, the explicit option).
30. **No compile-time clash check at the clause** (owner decision, 2026-10-14, review round
    2, option A). The builder's methods no longer intersect a callback's result (or a
    `limit`/`offset`/`lock` argument) with a check against the query's named parameters. A
    name used with two types across clauses gives the query a `never` parameter, so it
    cannot be given its params (a compile error where it runs), and the clause throws a
    `QueryError` that names it. Within one expression the check stays a compile error at
    the clause (step 07's `Compatible`). This is what lets reusable scopes chain clauses
    that add named parameters, and every method behaves the same in and out of scopes and
    after `hasNamedBinding`. `AddParams` infers the receiver's parts from its `"~query"`
    (so the compiler reads a scope's chain through the scope's constraint).
31. **Nullability is part of a named parameter's type at run time** (owner decision,
    2026-10-14, review round 2, option a). `param()` records a parameter declared with a
    nullable field type in a `WeakSet` of nodes (`NULLABLE_PARAMS`, `query/expr.ts`), once,
    when the node is made; the redaction rewrite carries the mark to the node it makes;
    `joinNamed` refuses one name used both ways, and its message says `integer | null`. The
    contract's `NamedParamNode` is unchanged.

## Known gaps

- **Expression errors raised inside a callback** name the clause and the operator
  (`where(): eq() was given null …`) but not always the field: that text comes from the
  expression layer (step 07).
- **The join form's type** accepts any alias whose binding is of the target schema; that
  it was joined *through that association* is checked at run time only (decision 16).
- **`exclude("preload")`** after a select of the whole root binding types the result as
  the root row, which is what it is; after other selects preloads cannot exist.
- **A JSON column of a scalar type** (`t.json<string>()`) takes a list in the object
  form's types but compares it as one whole value at run time: the types cannot tell a
  JSON column from a scalar one, only the value's type (decision 24).
- **A right or full join after a `select`, and a `preload` after a right or full join,**
  are refused at run time only (decision 25). Refusing them at compile time needs the query
  type to record whether it has a select or an optional root (a fifth type parameter, or
  more type-only members), which every method would then carry; after the depth problems of
  rounds 0 and 1 I left it out.
- **Two limits of scopes** (documented in the guide): a `select` inside a scope sees the
  scope's columns as nullable, since `QueryWith` accepts a left-joined binding; the object
  form of `where` does not compile there, since the root is unknown. A clash of a scope's
  named parameter with one of the query it receives is caught at run time, and gives the
  result a `never` parameter (decision 30).
- **`Sel<X>`** maps a value the select refuses at run time (an order item, a query, a
  function) instead of failing to compile; the run-time `QueryError` names the path.
- **Variance**: `Query` has no variance annotations. TypeScript could not verify `out B`
  (a key of `B` is used in `joinAssoc`'s constraints) and gave up on `R` and `P` as too deep;
  it measures them itself. Type tests compare queries through their `"~query"` member
  because comparing two `Query` types whole with `toEqualTypeOf` is too deep for it.

## Requests

**Step 09 (advanced queries)**

- A source wrapper implements `[AS_SOURCE](alias): SourceParts` (`query/builder.ts`) and
  the type-only `"~source": { binding, row, params }` (`SourceOperand<Bd, Rw, P>`); its
  binding object should be registered with `registerBinding` (`query/bindings.ts`) with
  the schema metadata when it has one, so that `select(({ r }) => r)` works, and carry the
  type-only `"~binding": { row, nullable }` member so that `Sel` types it.
- `.set(...)` / `.returning(...)`, set operations, CTEs and windows add properties the
  builder keeps per-property counts and hashes for (`COMBINATIONS` 11, `CTES` 12,
  `WINDOWS` 13, `UPDATES` 15, `HINTS` 17 in `QUERY_SHAPE_PROPERTIES` order); `#next` and
  `patched` need those indexes added (they handle the step-08 properties today).
- `exclude` should learn `"set"`, `"combinations"`, `"ctes"`, `"windows"` when they exist.
- The `filters.reduce((acc, f) => acc.and(f), dynamic.true())` pattern: a plain
  `reduce` keeps concrete parameters when the accumulator is typed with them
  (`reduce<Expr<boolean, Needed>>(…)`), and an accumulator typed with fewer does not
  compile (type tests in `builder.test-d.ts`); `dynamic.true()` needs to give the same.

**Step 10 (compiler)**

- `LockNode.clause` strings are `"FOR UPDATE"`, `"FOR SHARE"`, `"FOR NO KEY UPDATE"`,
  `"FOR KEY SHARE"`, each optionally followed by `" SKIP LOCKED"` or `" NOWAIT"`; the
  lock-mode table needs those eight entries plus the four bare ones.
- `limit` / `offset` from a number are `ParamNode`s typed `t.integer()`; from `param(...)`
  a `NamedParamNode`.
- A where-object filter with no keys is the literal `TRUE` in a `BoolNode`.
- Many-to-many join tables appear as table sources aliased `$<alias>_join` (a quoted
  identifier is needed: `$` is valid in Postgres identifiers only when quoted at the start).

**Step 12 (repo reads)**

- `QueryResult<Q>`, `QueryParams<Q>` and `Queryable` are exported; `Query.namedParams()`
  lists every name a query needs, its preload callbacks' included.
- `from(Schema, alias)` returns a cached root query: normalising a schema class to a query
  costs a lookup.

**Step 14 (preload)**
